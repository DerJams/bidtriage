stages that have not happened yet are marked *pending* and carry no timings or
costs, because none have been measured.

## Step 1 — Regenerate the eval corpus

The corpus is committed, so this is only needed to verify reproducibility.

```bash
python -m data.generate_pdfs
```

Renders the 5 RFP PDFs. reportlab runs in invariant mode, so output is
byte-identical across runs — verified by generating twice and comparing md5.
**Measured runtime: 324 ms.**

```bash
python -m data.extract_source_text
```

Writes the canonical plain text for all 12 cases. PDF text is what pdfplumber
actually extracts, not the authoring source, so gold spans can only cite text a
downstream consumer could really recover. **Measured runtime: 613 ms.**

```bash
python -m evals.author_gold
```

Authors and validates the 12 gold keys. Exits non-zero if any `source_span`
cannot be found verbatim in the extracted text. Prints the per-case present/
absent breakdown and derived triage. **Measured runtime: 165 ms.**

Expected output ends with:

```
TOTAL                                 88       8   (total slots: 96)

All gold spans verified verbatim against extracted source text.
```

### Verifying the PDFs survive a clone

```bash
python -m data.generate_pdfs && md5sum data/synthetic/pdfs/*.pdf
```

Compare against a fresh clone's PDFs. They must match — `.gitattributes` marks
PDFs binary specifically to prevent CRLF corruption on checkout. This was
verified against a clean clone.

## Step 2 / 3 — Baseline and eval harness

One command runs a target against all 12 cases, scores it deterministically
against the gold keys, and writes a timestamped JSON file to `evals/results/`:

```bash
python -m evals.run --target baseline
```

**Measured: 119 s wall clock per run, $0.00154 per run ($0.00013/case).**

Because temperature 0 is **not** deterministic on this provider, a single run is
not a measurement. Repeat runs spread 2.08 percentage points. Use n≥3:

```bash
for i in 1 2 3; do python -m evals.run --target baseline --label "run-$i"; done
```

Optional flags: `--cases case_01,case_12` to run a subset, `--model` to override
the model id (recorded in the results file), `--label` to tag the run.

### What a results file contains

`run_config` (model, routing mode, pinned provider, temperature), the resolved
provider for every call, per-slot outcomes, per-subcomponent bond diagnostics,
both hallucination denominators, the minutes proxy with its constants, retry
counts with reasons, any hard failures, and actual charged cost.

## Step 4 - Solution levers

Levers are selected with `BIDTRIAGE_LEVERS` and stack:

```bash
BIDTRIAGE_LEVERS=lever2_verify,lever3_triage,lever4_brief python -m evals.run --target solution
```

Measured per-run wall clock on the 12-case set: baseline 136 s, lever 2 341 s,
lever 2+3 654 s.

### Comparing arms

```bash
python -m evals.compare --a baseline --b lever2_verify+lever3_triage
```

An arm is named by its lever set, joined with `+`. The verdict rule is enforced
here rather than by judgement: an exact two-sided permutation test, with an
improvement requiring the delta to clear the larger observed spread and reach
p below 0.05. The noise floor is derived from the runs being compared, so it is
always empirical to whatever corpus it is run against.

### Running arms concurrently

Arms are I/O bound. Measured: three concurrent workers give a 3.56x speedup,
with retries rising only from 0.00 to 0.22 per case. Results filenames carry
microseconds and pid, so concurrent runs cannot overwrite one another.

### Corpus selection

```bash
BIDTRIAGE_CORPUS=v1 python -m evals.run --target baseline
BIDTRIAGE_CORPUS=v2 python -m evals.run --target baseline
```

v1 is the frozen 12-case set that every recorded result was measured on. The
corpus version also selects the bond field shape, because v2 splits general
liability into per-occurrence and aggregate limits, so v1 stays exactly
reproducible.

## Runtime and cost

| Stage | Runtime | API cost |
|---|---|---|
| Corpus generation (Step 1) | 1.1 s total, measured | none — no API calls |
| Harness selftest | < 1 s, measured | none — no API calls |
| Baseline, one run | 119 s, measured | $0.00154, actually charged |
| Baseline, n=4 protocol | ~8 min, measured | ~$0.0062, actually charged |
| Solution | pending | pending |

Cost is read from OpenRouter's `usage.cost` on each response — the amount
actually charged. It is never computed from a price table and never estimated.

### Upstream rate limits

With `allow_fallbacks: false` a 429 is a hard failure rather than something
OpenRouter reroutes around. The client retries with exponential backoff, capped
at 6 attempts, and records every retry with its reason plus any hard failure in
the results file. Observed: 2–6 retries per 12-case run, **0 hard failures**.
