Also constrains the Step-4 verification lever — it must cite spans that actually exist. |
| Step 1b — Triage derived, not asserted | Derived each case's bid/no-bid from `contractor_profile.json` rules instead of hand-writing it, so gold triage cannot drift from published criteria. | `derive_triage()` in `evals/author_gold.py` | Forced the capacity model to be explicit and falsifiable. | Step 1c — PDF corruption caught pre-submission | Commit warnings showed Git applying CRLF conversion to generated PDFs, which corrupts them on clone. Added `.gitattributes` marking PDFs binary. | Clean clone verified byte-identical to locally generated (md5 match) | A reproducibility bug that would have shipped silently and broken the corpus for anyone cloning. Verified by clone, not by assumption. |
| Step 1d — Trace capture scoped down | The Claude Code project directory holds 10 sessions / 28 MB, only one of them BidTriage. Wrote a capture script requiring explicit session ids with **no copy-all flag**, plus a credential redactor. | [`scripts/capture_traces.py`](scripts/capture_traces.py), [`traces/REDACTIONS.md`](traces/REDACTIONS.md) | A `cp -r` would have published unrelated transcripts to a public repo. First redactor version over-matched and ate the fictional `.example` addresses — fixed by moving the lookahead to the TLD. |

| Step 2a — Provider switch to OpenRouter | Instructed to move off the Anthropic API to z-ai/glm-5.3-flash on OpenRouter and "pin provider routing to Exacto". Verified both model ids exist before writing any code. | [`evals/config.py`](evals/config.py), OpenRouter models API | Both ids real. Anthropic SDK dropped entirely; the client is stdlib urllib, cutting dependencies from 24 packages to 9. |
| Step 2b — Exacto cannot be pinned (routing decision) | Auto Exacto is **not a selectable mode**. Per OpenRouter's docs it "runs by default on every tool-calling request, requiring no configuration" — it is opt-out, not opt-in, and applies **only to requests that include tools**. The baseline is a single toolless call, so Exacto would never have applied to it. Measured live, 3 runs per config: toolless unpinned went to **Z.AI** (no structured-output support); with tools unpinned went to **Together** at $0.15/$0.50; pinned went to **DeepInfra** at $0.075/$0.25. | [`evals/config.py`](evals/config.py) docstring; three-config live measurement | Leaving Exacto on would have run the baseline and the solution on **different providers at different prices with different structured-output support**, so every lever delta would have confounded my change with a provider change. Exacto also reorders on rolling 32-day live signals, so it is not stable across days. Pinned `only=[deepinfra]`, `allow_fallbacks=false`, `require_parameters=true`. Cheapest endpoint that supports structured outputs, and half the price of the one Exacto chose. The client verifies the resolved provider against the pin rather than trusting it. |
| Step 3 — Harness before baseline | Built the scorer first and ran a selftest before trusting it with any paid result. | `python -m evals.harness.selftest` exits 0 | Caught two normalizer bugs pre-flight: the corporate-suffix stripper ate the "CO" in every `City, CO` location, and splitting "process and hydronic piping" stranded "process" as a bogus trade. Added a rule that gold's hand-authored normalized values must be reproducible by the same normalizer the scorer uses — verified by planting a bad value and confirming detection. |
| Step 3a — Two scorer bugs that penalised correct answers | A single-case smoke run scored 4/8. Every failure was the harness, not the model. | [`docs/scoring-rules.md`](docs/scoring-rules.md) §6 | (1) `iso_date` used a word boundary that ISO datetimes lack, so the **more precise** `2026-09-25T14:00:00-06:00` scored unparseable. (2) `estimated_project_value` required a full-string numeric match, so a correctly extracted range with a trailing "(engineer estimate)" collapsed to a point value. Both fixes **raised the baseline's score** (95.8→96.9% on rescore) — they worked against my narrative interest, which is the evidence they were not motivated tuning. Amendments listed openly in the scoring rules rather than edited in silently. |
| **Step 2 — BASELINE (n=4 runs)** | One direct call, raw document text, no tools, no verification. Same structured-output schema and same contractor facts as the solution, so the comparison measures method rather than formatting or missing context. | [`evals/results/`](evals/results/) — 4 result files | **Field accuracy 95.05% mean** (min 93.75, max 95.83, sd 0.86). **Hallucination 3.16% mean** (min 2.30, max 4.60). **Triage 91.67%**, identical in all 4 runs. Cost **$0.00154/run**, $0.00013/case. 0 hard failures, 5–6 retries/run on upstream 429s. |
| Step 2c — Baseline already clears the accuracy bar | Compared the measured baseline against the targets frozen before measurement. | Same 4 result files | **The 90% field-accuracy target is already met by the baseline (95.05%).** The ≤2% hallucination target is **not** (3.16%). So the primary metric has almost no headroom and the real, reproducible weaknesses are elsewhere: abstention discipline and triage criteria. Reported rather than papered over. |
| Step 2d — Temperature 0 is not deterministic | Re-running the identical config gave different scores, so ran the baseline 4× to establish a noise floor before attributing anything to a lever. | 4 result files; per-slot stability table | Spread **2.08 percentage points** (2 slots), sd 0.86. **Any lever delta below ~2pp is indistinguishable from noise at n=1**, so every future comparison uses n=3 minimum. Separated 4 **systematic** failures (fail 4/4: case_02 value, case_04 title, case_08 bond, case_10 trade) from 2 **flaky** ones (case_05 title 2/4, case_06 trade 1/4). The systematic four are the only real lever targets. |
